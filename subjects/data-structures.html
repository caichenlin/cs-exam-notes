重點整理

時間複雜度 Big-O

Big-O 描述「資料量 n 變大時，執行時間最多會長多快」，只看最高次項、忽略常數。例如迴圈跑 3n + 5 次，就寫成 O(n)；兩層各跑 n 次的巢狀迴圈是 O(n²)。比較演算法時，重點是成長速度，而不是在小資料上誰比較快。

Array 與 Linked List

Array 的元素在記憶體中連續存放，所以用索引讀取是 O(1)，但在中間插入或刪除要搬移後面的元素，是 O(n)。Linked List 要從頭一個一個走才能讀到第 i 個，所以讀取是 O(n)；但只要已經拿到那個節點的位置，插入或刪除只要改指標，就是 O(1)。

Stack 與 Queue

Stack 是後進先出（LIFO），像疊盤子，只能從最上面放和拿；常用於函式呼叫、括號配對、中序轉後序。Queue 是先進先出（FIFO），像排隊；常用於 BFS 與工作排程。兩者的 push／pop（enqueue／dequeue）都是 O(1)。

Binary Tree 走訪

三種深度優先走訪的差別只在「什麼時候拜訪根」：前序（根、左、右）、中序（左、根、右）、後序（左、右、根）。對 Binary Search Tree 做中序走訪，會得到由小到大排好的序列。

void inorder(Node *t) {
    if (t == NULL) return;
    inorder(t->left);
    visit(t);
    inorder(t->right);
}

Heap 與 Priority Queue

Heap 是一棵完整二元樹，Min-Heap 規定「每個父節點都不大於子節點」，所以最小值永遠在根。通常用陣列存：索引 i（從 0 開始）的左右子節點在 2i+1、2i+2。插入與刪除最小值都是 O(log n)，因此很適合拿來實作 Priority Queue。

Graph 的 BFS 與 DFS

Graph 常用 adjacency matrix（O(V²) 空間）或 adjacency list（O(V+E) 空間）表示。BFS 用 Queue，一層一層往外擴展，在無權重圖中可找到最短路徑；DFS 用 Stack（或遞迴），一路走到底再回頭。用 adjacency list 時，兩者的時間複雜度都是 O(V+E)。

考古題解析

題型概述
給定一棵二元樹的前序走訪 A B D E C F 與中序走訪 D B E A F C，求後序走訪。
解析
前序的第一個一定是根，所以根是 A。在中序裡 A 的左邊（D B E）是左子樹、右邊（F C）是右子樹。左子樹在前序中是 B D E，根為 B，再對照中序可知 D 在 B 左、E 在 B 右。右子樹在前序中是 C F，根為 C，中序 F C 表示 F 是 C 的左子節點。最後依「左、右、根」寫出後序：D E B F C A。

題型概述
依序將 5, 3, 8, 1, 4, 2 插入一個空的 Min-Heap，寫出陣列內容；再執行一次刪除最小值，寫出結果。
解析
每次插入都放到陣列最後，再和父節點比較，比較小就往上交換（sift-up）。依序插入後得到 [1, 3, 2, 5, 4, 8]。刪除最小值時，取出根 1，把最後一個元素 8 移到根，再和較小的子節點往下交換（sift-down）：8 與 2 交換後已無子節點，結果為 [2, 3, 8, 5, 4]。

易錯題

  • 錯誤觀念：Binary Search Tree 的搜尋一定是 O(log n)。
    正確說法：O(log n) 只在樹大致平衡時成立。若依序插入已排序的資料，樹會退化成一條鏈，搜尋變成 O(n)；要保證 O(log n) 需使用 AVL Tree 等平衡樹。
  • 錯誤觀念：Heap 的陣列是排好序的。
    正確說法：Heap 只保證「父節點與子節點」之間的大小關係，兄弟之間、不同層之間沒有順序，例如 [1, 3, 2, 5, 4, 8] 是合法的 Min-Heap，但並未排序。
  • 錯誤觀念：把 n 個元素建成 Heap 一定要 O(n log n)。
    正確說法：逐一插入是 O(n log n)，但用由下而上的 heapify（從最後一個非葉節點往前做 sift-down）建堆，總時間是 O(n)。
